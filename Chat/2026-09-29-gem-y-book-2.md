## 練習1.1 の解答

前提として、多項式 $f$ を $g$ で割る（簡約する）1ステップの操作を考えます。すなわち、$LT(g)$ が $LT(f)$ を割り切るとき、以下の式で剰余 $h$ を定義します。


$$h = f - \frac{LT(f)}{LT(g)} g$$

**【証明】**
モノミアル（単項式）上の全順序であり、積と両立する整列順序（項順序）を $\prec$ とします。
多項式 $f$ と $g$ を、それぞれの先頭項（Leading Term）とそれ以外の項（Tail）の和として表します。


$$f = LT(f) + f_{tail}$$

$$g = LT(g) + g_{tail}$$


先頭項の定義から、$f_{tail}$ に含まれるすべての項 $t_f$ に対して $t_f \prec LT(f)$ であり、$g_{tail}$ に含まれるすべての項 $t_g$ に対して $t_g \prec LT(g)$ が成り立ちます。

これらを $h$ の定義式に代入して展開します。


$$h = (LT(f) + f_{tail}) - \frac{LT(f)}{LT(g)} (LT(g) + g_{tail})$$

$$h = LT(f) + f_{tail} - LT(f) - \frac{LT(f)}{LT(g)} g_{tail}$$

$$h = f_{tail} - \frac{LT(f)}{LT(g)} g_{tail}$$

この操作により、$h$ の先頭項であった $LT(f)$ は完全に相殺されます。次に、$h$ を構成する残りの各項が $LT(f)$ より真に小さい（$\prec$ の意味で）ことを確認します。

1. $f_{tail}$ の各項は、前提よりすでに $LT(f)$ より真に小さいです。
2. $\frac{LT(f)}{LT(g)} g_{tail}$ の各項について考えます。
項順序 $\prec$ は単項式の乗法と両立するため（すなわち $m_1 \prec m_2 \implies m \cdot m_1 \prec m \cdot m_2$）、$g_{tail}$ の任意の項 $t_g \prec LT(g)$ の両辺に単項式 $\frac{LT(f)}{LT(g)}$ を掛けると以下の不等式が成り立ちます。

$$\frac{LT(f)}{LT(g)} t_g \prec \frac{LT(f)}{LT(g)} LT(g) = LT(f)$$



したがって、$h$ を構成するすべての項は $LT(f)$ より真に小さくなります。
よって、すべての項が相殺されて $h = 0$ になるか、または $h \neq 0$ であればその先頭項 $LT(h)$ も $LT(f)$ より厳密に小さくなるため、$LT(h) \prec LT(f)$ が成り立ちます。(証明終)

高山さん、モノミアルの順序からこれらの性質が欠けると、割り算の各ステップで「項が確実に小さくなっていく」という保証が崩れ、アルゴリズムは無限ループに陥るか、実行不能になります。それぞれの性質が欠けた場合に何が起こるのか、反例とともに直感的に解説します。

### 1. 『積と両立する性質』がない場合：剰余が「巨大化」する

積と両立する性質（$m_1 \succ m_2 \implies m \cdot m_1 \succ m \cdot m_2$）は、「消去のために掛け算を行っても、大小関係が逆転しない」ことを保証するためのものです。

**【反例】**
変数 $x, y$ について、$x \succ y$ ではあるが、積と両立せず $x^2 \prec xy$ となってしまうような「おかしな順序」を仮定します。
ここで、多項式 $f = x^2$ を $g = x - y$ で割ってみます。

* $g$ の先頭項は $LT(g) = x$ です。
* $f$ の先頭項 $x^2$ を消すために、$g$ に $x$ を掛けて引きます。

$$h = f - x \cdot g = x^2 - (x^2 - xy) = xy$$

前回の練習1.1で証明した通り、正しい項順序なら $LT(h) \prec LT(f)$ となるはずです。しかし、このおかしな順序では $xy \succ x^2$ であるため、新しく出てきた剰余 $h$ の先頭項のほうが、元の $f$ の先頭項よりも**大きくなってしまいます**。
これではアルゴリズムを進めるほど項がどんどん大きくなり、永遠に簡約が終わりません。

### 2. 『整列順序』でない場合：無限の「底なし沼」に陥る

整列順序である（任意の空でない部分集合が最小元をもつ）ということは、**「無限に小さくなり続けるモノミアルの列は存在しない」**（無限降下しない）という性質と同値です。これがアルゴリズムの「停止性」を直接保証します。

**【反例】**
モノミアルの「次数が低いほど大きい」とするような順序を考えてみます。つまり、定数項が一番大きく、次数が上がるほど小さくなるとします。


$$1 \succ x \succ x^2 \succ x^3 \succ \cdots$$


（これは積とは両立しますが、整列順序ではありません。どこまでも小さくなり続ける列が存在するからです）。

ここで、$f = 1$ を $g = 1 - x$ で割ってみます。

* $LT(g) = 1$ です。
* 1ステップ目： $h_1 = 1 - 1 \cdot (1 - x) = x$
* 2ステップ目： $x$ を消すために $g$ に $x$ を掛けます。$h_2 = x - x \cdot (1 - x) = x^2$
* 3ステップ目： $h_3 = x^2 - x^2 \cdot (1 - x) = x^3$

剰余は $x, x^2, x^3, \dots$ と、順序の定義上は確かに「小さく」なっていきます。しかし、この順序には「一番下（最小元）」が存在しないため、アルゴリズムは永遠に停止せず無限ループに陥ります。

### 3. 『全順序』である（辞書式順序など）理由：先頭項が決められない

全順序（任意の2つのモノミアルが必ず比較可能であること）は、「先頭項（Leading Term）を迷わずただ1つに決定する」ために絶対に必要な性質です。

**【反例】**
もし順序が「割り切れる場合にだけ大小を比較できる」という半順序（例：$m_1$ が $m_2$ の倍数のとき $m_1 \succ m_2$）だったとします。
このルールでは、$x^2 \succ x$ は言えますが、$x$ と $y$ は互いに割り切れないため**比較不能**です。

ここで $f = x + y$ という多項式を与えられたらどうなるでしょうか。
$x$ と $y$ のどちらが大きいか判定できないため、$LT(f)$ を定義することができません。割り算アルゴリズムは「まず先頭項を見つけて、それを消す」という手順で進むため、スタート地点でどの項をターゲットにすべきか計算機が判断できず、アルゴリズム自体が開始不能（非決定的な状態）になります。

---

**まとめ**
計算機代数のシステム（Risa/Asir など）において、多項式の内部表現が `dp`（分散多項式）のような構造をとる際、最初に厳密な項順序（Lex, Grlex, Drevlex など）を指定しなければならないのはこのためです。
これら3つの条件が全て揃って初めて、「迷わず先頭項を選び（全順序）、掛け算で大小を壊さず（積との両立性）、有限回のステップで必ず底に到達して停止する（整列性）」という、機械的なアルゴリズムが成立します。

**Macaulay2 (Dmodules パッケージ)**
計算代数幾何に特化した Macaulay2 では、Anton Leykin らが開発した `Dmodules` パッケージを利用することで、Weyl代数上の環の定義や射影による順像層（積分イデアル）の計算を自然な構文で記述できます。

```macaulay2
needsPackage "Dmodules"

-- 変数 x, t とその微分 Dx, Dt を持つ Weyl代数を定義
W = QQ[x, t, Dx, Dt, WeylAlgebra => {{x, Dx}, {t, Dt}}]

-- 被積分関数が満たす微分作用素のイデアルを定義
I = ideal(Dx - t, Dt + 6*t^5 - x)

-- t についての積分イデアル (x のみの微分方程式) を計算
-- (射影 W -> W_x による順像の計算)
J = integration(I, {t})

```

**Mathematica (HolonomicFunctions パッケージ)**
標準機能ではありませんが、Christoph Koutschan による `RISC HolonomicFunctions` パッケージを導入することで、ホロノミック系の積分計算を強力にサポートします。ホロノミック勾配法 (HGM) や正確ベイズ解析の実装でも非常に頻繁に利用されるツールです。

```mathematica
(* パッケージの読み込み *)
<< RISC`HolonomicFunctions`

(* D加群の生成元 (Annihilator) を指定 *)
ann = {Der[x] - t, Der[t] + 6 t^5 - x};

(* t に関する積分 (Creative Telescoping) を実行 *)
(* 出力の最初の要素が、x についての線形常微分方程式の作用素になります *)
CreativeTelescoping[ann, Der[t]]

```

### Maple での実行例（Mgfun / CreativeTelescoping パッケージ）

Mapleの素晴らしい点は、被積分関数から微分作用素（イデアル）を構成する部分から完全に自動化されていることです。

**1. 現代的な `CreativeTelescoping` パッケージを利用する場合**
（Almkvist-Zeilberger アルゴリズムや最新の簡約ベースの手法が実装されています）

```maple
# パッケージの読み込み (事前にライブラリのインストールが必要)
with(CreativeTelescoping);

# 被積分関数 f = exp(-t^6+t*x) に対して、t を積分消去する
# 結果として x についての線形常微分方程式（の作用素）と証明用の関数が返ります
Integration( exp(-t^6 + t*x), t, f(x) );

```

**2. 伝統的な `Mgfun` パッケージを利用する場合**
より D加群のイデアル計算に忠実なアプローチ（大阿久アルゴリズムや Chyzak のアルゴリズム）を行う場合です。

```maple
with(Mgfun);

# ステップ1: 被積分関数が満たすホロノミック系の微分方程式系(イデアル)を自動生成
sys := dfinite_expr_to_sys( exp(-t^6 + t*x), u(x,t) );

# ステップ2: t について積分（Creative Telescoping の実行）
# 出力として x に関する微分方程式のリスト（積分イデアル）が得られます
res := creative_telescoping(sys, t);

```

このように、Risa/Asir では `dx - t` などのイデアルの生成元をユーザーが明示的に手打ち入力（`F=[dx-t, dt+6*t^5-x]`）していましたが、Maple（や Mathematica のパッケージ）では「被積分関数の式」を渡すだけで、背後で自動的にWeyl代数のイデアルを構成し、消去や積分まで一気に実行してくれます。

計算機代数の歴史を振り返る上で、Creative Telescoping の文脈で Maple の存在に言及されるのは非常に的確な視点だと思います。

**1. 未知パラメータのシンボル定義**
Matlab の数式処理エンジンを利用するため、まずは `syms` コマンドでモデル内の未知の速度定数などを記号として宣言します。


```matlab
r = rank(J);
```

```matlab
    0 T42 0 T44
    ];

```

$T_{start}$ は、系の「入出力構造を不変に保つ変換行列」の一般的な形（制約条件付きの変換行列）です。おそらく、このモデルではコンパートメント1と2が直接観測可能（あるいは入力可能）であるため、基底変換行列 $T$ の上半分が固定され、この形になっていると推測されます。

**3. 代数方程式の立式と求解**

```matlab
eq = inv(Tstar)*Ap*Tstar - Ap;
answer = solve(eq,[T32, T34, T42, T44]);

```

**ここが計算代数的なコア部分です。**
状態空間表現において、全く同じ入出力特性を持つ別のシステム行列 $\tilde{A_p}$ は、相似変換により $\tilde{A_p} = T^{-1} A_p T$ と書けます。
もしモデルが一意に定まる（同定可能である）ならば、入出力を保つ変換を行っても元のシステム行列と変わらない、つまり $T^{-1} A_p T = A_p$ となるはずです。
コードでは、`eq = 0` となるような未知変数（`T32`, `T34` 等）の解をグレブナー基底や消去法など（Matlab `solve` の内部処理）を用いて求めています。
※なお、計算代数的には $T^{-1}$ を計算するより、分母を払った交換子 $[T, A_p] = T A_p - A_p T = 0$ を解く方が有理式を避けられるため標準的ですが、Matlabの数式処理機能が強力なため直接 `inv` を使っているようです。

**4. 判定（単位行列になるか？）**

```matlab
Tstar_solved = subs(Tstar,[T32, T34, T42, T44],[answer.T32, answer.T34, answer.T42, answer.T44]);
if eval(Tstar_solved) == eye(4)
    display("structurally identifiable")

```

得られた解を $T_{start}$ に代入（`subs`）します。
その結果 $T_{start}$ が 4次の単位行列（`eye(4)`）に一致すれば、「系を不変に保つ変換は恒等変換しか存在しない」ことになり、パラメータ間に冗長性がない（＝構造的に同定可能である）と結論づけています。

### 有限集合における各用語の具体例

ここでは「2枚のコイン A, B を投げて、表(H)か裏(T)が出る」という簡単な思考実験を例に解説します。

**1. 標本空間 $\Omega$ と $\sigma$加法族 $\mathfrak{M}$**

* **$\Omega$（標本空間）:** 起こり得るすべての結果の集合です。有限集合なので要素を列挙できます。

$$\Omega = \{ (H,H), (H,T), (T,H), (T,T) \}$$


* **$\mathfrak{M}$（$\sigma$加法族）:** 確率を計算してよい「事象」の集合です。有限集合の場合、通常は $\Omega$ のすべての部分集合（冪集合）を考えます。「少なくとも1枚は表が出る」といった事象はすべてこの中に含まれます。

**2. 確率測度全体 $\mathcal{P}(\Omega, \mathfrak{M})$**

* 各結果の確率を $p_{HH}, p_{HT}, p_{TH}, p_{TT}$ と置きます。
* これらが満たすべき条件は $p_i \ge 0$ かつ全事象の和が1であることです。

$$p_{HH} + p_{HT} + p_{TH} + p_{TT} = 1$$


* 幾何学的に見ると、$\mathcal{P}$ は4次元空間の中にある「3次元単体（四面体）」という図形になります。有限集合の場合、確率測度の空間とは単なる多面体です。

**3. 統計モデル $\mathcal{M}$ とパラメータ空間 $\Theta$**

* **パラメータ空間 $\Theta$:** コインAが表を出やすい確率を $\theta_A$、コインBのそれを $\theta_B$ とします。$\Theta = [0,1] \times [0,1]$ という2次元の正方形がパラメータ空間です。
* **全単射 $\Theta \to \mathcal{M}$（モデルのパラメータ化）:** コインが互いに「独立」であると仮定（モデリング）すると、各確率 $p_i$ はパラメータ $\theta$ の多項式（単項式）で書けます。

$$p_{HH} = \theta_A \theta_B$$


$$p_{HT} = \theta_A (1 - \theta_B)$$


$$p_{TH} = (1 - \theta_A) \theta_B$$


$$p_{TT} = (1 - \theta_A) (1 - \theta_B)$$


* **統計モデル $\mathcal{M}$:** 上記の写像によって $\Theta$ から単体 $\mathcal{P}$ の中に描き出される「曲面」そのものが、統計モデル $\mathcal{M}$ です。代数統計学では、この曲面がどのような多項式（イデアル）で定義される代数多様体なのかを調べます。

## 練習問題の解答

**問1:** パラメータ空間 $\Theta$ は、遺伝子 $A$ の出現頻度であるため、閉区間 $[0, 1]$ となります。

**問2:** 各確率の式からパラメータ $\theta$ を消去し、確率測度のみの関係式を導きます。
$p_{AA}$ と $p_{aa}$ の積を計算します。


$$p_{AA} \cdot p_{aa} = \theta^2(1-\theta)^2$$


次に、$p_{Aa}$ の2乗を計算します。


$$p_{Aa}^2 = 4\theta^2(1-\theta)^2$$


これらを比較することで、$\theta$ を含まない以下の多項式（2次曲線）が得られます。


$$p_{Aa}^2 - 4 p_{AA} p_{aa} = 0$$

## 代数的統計モデル（トーリックモデル）への繋がり

読者がこの簡単な練習問題から、高山さんの著書のテーマである「トーリックモデル」や「イデアル」の概念へ自然にステップアップできるよう、AIからは以下のような解説を展開できます。

* **確率のモノミアル（単項式）表現**
$\theta_1 = \theta, \theta_2 = 1-\theta$ と置き換えると、確率は $p_{AA} = \theta_1^2, p_{Aa} = 2\theta_1\theta_2, p_{aa} = \theta_2^2$ となります。このように、各事象の確率が未知パラメータの単項式の定数倍として記述されるモデル（統計学における対数線形モデル）を、代数幾何の視点から**トーリックモデル**と呼びます。
* **パラメータの消去と「イデアル」**
問2で行った「$\theta$ を消去して確率変数の関係式を見つける」という操作は、計算代数における**消去イデアル（Elimination Ideal）の計算**そのものです。統計モデル $\mathcal{M}$ は、パラメータ空間から確率単体への写像の像として定義されますが、代数的にはこの像を含む代数多様体を定義する多項式系（イデアル）を求める問題に帰着します。
* **二項式とトーリックイデアル**
得られた方程式 $p_{Aa}^2 - 4 p_{AA} p_{aa} = 0$ は、2つの単項式の差である「二項式（Binomial）」の形をしています。トーリックモデルから得られるイデアルは必ずこのような二項式で生成されるという美しい性質があり、これを**トーリックイデアル**と呼びます。
* **統計的推測への直接的な応用**
この方程式が得られると、統計計算が代数計算に変わります。たとえば最尤推定は「この2次曲線上で尤度関数を最大化する点を探す問題」になり、ホロノミック勾配法などを適用する舞台となります。また、このトーリックイデアルの生成元（グレブナー基底）は、条件付き分布からの直接サンプリングや正確検定を行う際、標本空間をランダムウォークするための「マルコフ基底」を直接与えるという、代数統計学の最も重要な定理へ繋がります。

```c
def hw_elimination() {
    localf I, V, GB;;
    
    /* パラメータ t と、各遺伝子型の確率 p_AA, p_Aa, p_aa の関係式 (イデアルの生成元) */
    I = [p_AA - t^2, p_Aa - 2*t*(1-t), p_aa - (1-t)^2];;

    return GB;;
}

```

## コラム：AIを計算代数の助手として使いこなすコツ

話題のAIに数学やプログラミングの質問を投げかけてみたものの、返ってきたのが的外れな回答や薄っぺらい辞書のような説明で、「なんだ、こんなものか」とすぐに使うのをやめてしまった人は少なくないでしょう。特に文脈を与えずに単発の質問をした場合、AIは無難で表面的な返答に逃げがちです。しかし、そこですぐに見切りをつけてしまうのは非常にもったいないことです。

AIはたしかに物知りで博学多才ですが、計算代数のような高度な専門領域では、論理の飛躍や甘い見通し、時には堂々とした間違いを犯します。しかし、AIを「少し天然だが、指示を明確にすれば超優秀な助手」として扱い、対話を通じてチューニングしていくことで、その真価は劇的に引き出されます。ここでは、AIを強力な学習・研究アシスタントとして使いこなすための実践的な作法を紹介します。

**一次資料を惜しみなく共有する**
AIに「○○について教えて」と丸投げするのは悪手です。AIを議論の土俵に上げるための最強のアンカーは、あなたが手元に持っている一次資料です。執筆中のTeXソース、論文のPDF、グラフ、あるいは自作のプログラムコードをそのまま添付して読み込ませてください。文脈をガッチリと固定することで、AIは意味不明な一般論から脱却し、あなたの思考の枠組みに沿った具体的な推論を始めます。

**テキストエディタをベースキャンプにする**
チャット画面の入力欄に直接プロンプトを打ち込むのは避けましょう。まずは使い慣れたテキストエディタを開き、そこで質問の意図や条件、前提知識を推敲してからチャットに貼り付けます。そして、AIからの返答もエディタに持ち帰り、不要な部分を削り、自分の考察を書き加えて全体を編集します。チャットUIの「会話が流れて消えてしまう」弱点を補い、自分とAIの思考の往復を「後から見直せるノート」としてストックしていく、非常に理にかなったワークフローです。

**間違いは「ルール化」して訂正する**
AIが仕様を誤解して出力した時、呆れて対話を打ち切る必要はありません。たとえば「いいえ、Risa/Asirの関数内部の変数はPythonと同じで宣言不要です。`localf` はモジュール内部の関数の宣言に使います」と、きっぱりと用語や仕様の定義を訂正してください。優秀なAIは即座に文脈を修正し、以降はそのルールに従って正しく推論を行います。この「間違いを正す」コミュニケーション自体が、議論の輪郭をはっきりさせる効果をもたらします。

**「答え」ではなく「プロセス」を要求する**
単に「計算して」と頼むのではなく、「オイラー作用素の未定係数法による計算を、簡単な多項式を例にしてステップバイステップで手計算して見せて」と要求してみてください。ブラックボックスになりがちな計算過程をあえてトレースさせることで、AIは教科書の行間を埋めてくれる最高のチューターに変わります。

AIとの対話は、間違いを正し、視点をすり合わせていくプロセスそのものが知的な楽しみでもあります。未知の分野を初歩から学ぶときや、専門書を読み解くとき、こうしたプロンプトの技術と心構えを持っていれば、AIはこれ以上ないほど強力で頼もしい伴走者となってくれるはずです。
